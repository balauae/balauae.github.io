How It Works13 / 20
How It Works
THE GROWING
CONVERSATION
Every turn, the full conversation is sent to the LLM.
Here's what that looks like under the hood:
TURN 1
TURN 2
SYSTEM You are a campus assistant. tools: [ get_events, get_faculty, search_notices ]
USER "What events are happening this month?"
ASSISTANT { tool_call: "get_events", args: { month: "sept" } }
TOOL { result: ["Hackathon Sept 15", "Tech Fest Sept 20", "AI Workshop Sept 25"] }
ASSISTANT "Hackathon (Sept 15), Tech Fest (Sept 20), AI Workshop (Sept 25)!"
follow-up — all above is resent + new messages
USER "Which one is good for beginners?"
ASSISTANT "AI Workshop on Sept 25 — it's designed for first-timers!"
The LLM sees the entire history every turn — it knows "which one" means events. That's why context windows matter.
Key Components14 / 20
Key Components
HOW AGENTS
REMEMBER: MEMORY
SHORT-TERM (Context Window)
You: What events are happening this month?
Agent: Hackathon, Tech Fest, AI Workshop
You: Which one is for beginners?
→ Knows "which one" refers to events, not departments
Lives inside the conversation. Gone when chat ends.
LONG-TERM (Persisted Store)
Saved across sessions — the agent remembers you:
3rd year student→ tailors depth
Asked about placements→ proactive updates
Interested in hackathons→ notifies about new ones
Stored in a database or file. Survives restarts.
